# ProjectOS

## Start

1. Identify the outcome, owner, audience, constraints, and stakes.
2. Choose Lite, Standard, Advanced, or Program mode.
3. Locate or create the Charter, Source of Truth Register, decisions, assumptions, risks, and Definition of Done.
4. Select one primary outcome for the current task.
5. Create a Context Manifest containing only the relevant context.

Read `references/operating-system.md` when designing the project lifecycle, quality model, handoff, or batch process.

## Execute

1. Inspect sources before producing the final artifact.
2. Separate confirmed facts, assumptions, proposals, and decisions.
3. Preserve originals and create reviewable changes.
4. Verify current capability maturity and minimum permissions.
5. Run a pilot before scaling a template or batch.
6. Keep independent tasks separate when they can run safely in parallel.
7. Stop before any external, public, paid, sensitive, or irreversible action that lacks explicit approval.

## Verify

Test the output against:

- the stated outcome and Definition of Done;
- authoritative sources and freshness;
- logical and domain correctness;
- requirements coverage;
- privacy, security, and permissions;
- usability and accessibility;
- release and rollback readiness.

Use a reviewer distinct from the producer for material outputs.

## Close

1. Record the gate result and unresolved limitations.
2. Publish or deliver only the approved snapshot.
3. Update decisions, risks, status, and dependencies.
4. Create a Handoff Pack with the exact next action.
5. Report what changed, how it was verified, remaining risks, and the next step.

Never mark work complete merely because files were created.
