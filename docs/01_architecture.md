# Архитектура Project OS

## Назначение и границы

Система управляет проектным контекстом, решениями, качеством, передачей работы и воспроизводимостью результата. Она не заменяет владельца проекта, юридическую/финансовую экспертизу, корпоративные права доступа, резервное копирование и специализированные системы учета.

## Компоненты

| Контур | Что хранит/делает | Главный выход |
|---|---|---|
| Governance | границы, полномочия, уровни сложности | Charter, Project DNA |
| Knowledge | источники, сущности, термины, уверенность | SoT Registry, Knowledge Map, Glossary |
| Delivery | этапы, workstreams, задачи, зависимости | план и артефакты |
| Context | отбор минимального набора материалов | Context Manifest |
| Assurance | критика, фактчек, согласованность, приемка | QA Report, решение Gate |
| Continuity | фиксация решений и передача контекста | Decision Log, Handoff Pack |
| Improvement | ретроспектива и контролируемые изменения | OS Change Proposal/Log |

## Уровни управления

1. **Project OS baseline** — универсальные правила. Меняется только через ретроспективу, тест и утверждение.
2. **Program rules** — общие правила группы проектов; не могут ослаблять baseline без зафиксированного исключения.
3. **Project DNA** — устойчивые правила конкретного проекта.
4. **Stage brief** — цель и ограничения этапа.
5. **Work task** — одна исполнимая задача с одним результатом.

При конфликте действует более высокий уровень, кроме явно утвержденного исключения с владельцем, сроком и причиной.

## Человек и AI

AI автономно: инвентаризирует доступные материалы; создает черновики; классифицирует; выявляет дубли и противоречия; предлагает план; обновляет неутвержденные реестры; готовит проверки и handoff; выполняет обратимые организационные действия в разрешенной области.

Человек всегда решает: цели и бизнес-компромиссы; доступ к чувствительным данным; публикацию; платежи и обязательства; удаление/перезапись единственной копии; юридически или репутационно значимые утверждения; принятие высокого остаточного риска; изменение Approved Project DNA; финальное утверждение критических результатов.

## Модель статусов

`Proposed -> Draft -> Review -> Approved -> Superseded -> Archived`.

- `Proposed`: идея еще не принята в работу.
- `Draft`: рабочая версия, использовать как истину нельзя.
- `Review`: заморожена для проверки; изменения возвращают в Draft.
- `Approved`: действующая версия и разрешенный источник решений.
- `Superseded`: заменена указанной Approved-версией.
- `Archived`: закрыта и исключена из рабочего контекста.

## Definition of Done проекта

Проект завершен, когда результат принят по критериям Charter; источники и решения прослеживаются; критические QA-проверки пройдены; зависимые документы обновлены; открытые риски переданы владельцам; опубликована утвержденная версия; рабочие материалы архивированы; проведена ретроспектива; улучшения Project OS либо утверждены, либо отклонены с причиной.
