# Operating Model

## Lifecycle

### Discover

Clarify the desired outcome, audience, constraints, stakes, and available evidence.

### Define

Create the Charter, Project DNA, source register, risks, and Definition of Done.

### Design

Split the project into independently verifiable stages. Assign an owner, input contract, output contract, dependencies, and gate to each stage.

### Execute

Create one focused task per primary outcome. Supply a Context Manifest instead of the full project archive.

### Verify

Run automated checks, evidence review, independent critique, and human approval where required.

### Release

Publish an atomic approved snapshot. Record the version, date, release notes, limitations, and rollback.

### Learn

Run a retrospective. Change ProjectOS only through a documented proposal with evidence and rollback.

## Status model

| Status | Meaning |
|---|---|
| Draft | incomplete and changeable |
| Review | ready for evaluation |
| Approved | accepted by the named owner |
| Released | published or delivered |
| Superseded | replaced by a newer approved version |
| Archived | retained for history, not active use |

## Long-running goals

A durable goal contains:

- **Outcome:** what must exist or change;
- **Constraints:** boundaries, compatibility, tools, cost, and forbidden approaches;
- **Verification:** tests, measurements, or review criteria proving completion.

Keep related work in one project. Use separate sessions for distinct outcomes and a handoff whenever execution moves between people, agents, or surfaces.
