# Adoption and Governance

ProjectOS should reduce rework, not create ceremony.

## Seven-day adoption

### Day 1

Choose one real Standard-mode project. Define its owner and outcome.

### Day 2

Create the Charter, source register, decisions, assumptions, and risks.

### Day 3

Design stages and workflow cards. Establish approval boundaries.

### Day 4

Run one focused task with a Context Manifest.

### Day 5

Run an independent Quality Gate and record findings.

### Day 6

Create a Handoff Pack and test continuation in a fresh session.

### Day 7

Release the result, run a retrospective, and remove unnecessary process.

## Ownership

| Role | Responsibility |
|---|---|
| Project Owner | outcome, priorities, final approval |
| Steward | registers, versions, handoffs, process integrity |
| Producer | creates the output |
| Reviewer | independently tests the output |
| Domain Expert | validates specialist claims and constraints |

One person may hold several roles in small projects, but material outputs still need a distinct review pass.

## Controlled improvement

A methodology change needs:

- observed problem;
- evidence and affected workflows;
- proposed change;
- expected benefit;
- risk and compatibility impact;
- validation method;
- owner and status;
- rollback.

Do not change stable rules merely because one output was unsatisfactory. Fix the narrowest cause that evidence supports.
