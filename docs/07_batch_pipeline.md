# Массовые задачи и производственный конвейер

## Конвейер

1. Инвентаризация исходных данных и прав.
2. Очистка с сохранением raw-копии.
3. Дедупликация по явным правилам.
4. Классификация.
5. Определение сущностей и стабильных ID.
6. Выявление конфликтов и карантин спорных строк.
7. Версионирование схемы/шаблона/правил.
8. Пилотная партия.
9. Независимая проверка пилота.
10. Коррекция правил с повторным пилотом при смысловых изменениях.
11. Пакетное производство.
12. Автоматические контрольные проверки.
13. Стратифицированная ручная выборка.
14. Финальная сборка.
15. Экспорт и проверка импорта/открытия.
16. Журнал ошибок и повторная обработка только дефектных единиц.
17. Ретроспектива и предложение изменений методологии.

## Контракт запуска

До массового производства зафиксировать: `run_id`; версии входного среза, схемы, шаблона и правил; уникальный `item_id`; размер партии; лимит времени/стоимости; checkpoint; критерии остановки; стратегию ошибок; размер и метод выборки; формат финального отчета.

## Идемпотентность и возобновление

Ключ обработки: `item_id + input_hash + rules_version + template_version`. Если комбинация уже имеет статус `passed`, повторная обработка запрещена без явного `force_reason`. После остановки продолжать с последнего атомарно завершенного checkpoint, а не с начала партии.

Статусы единицы: `queued -> processing -> produced -> qa_passed | qa_failed | quarantined -> exported`.

## Размер партии

Первая партия 5–20 единиц, затем размер увеличивается только после прохождения пилота. Партия должна быть достаточно мала, чтобы ее можно было повторить в пределах допустимого бюджета и вручную расследовать общий дефект. Не менять правила в середине партии; новое правило создает новую версию и новый run segment.

## Выборочная проверка

Выборка включает: случайные элементы; каждый класс; крайние значения; элементы с низкой уверенностью; все типы ошибок; первые и последние элементы партии. При критическом дефекте — остановить поток и проверить весь затронутый сегмент. Порог приемки задается до запуска, не после просмотра результатов.

```markdown
# Batch Run Report — [run_id]
- Входной срез / хеш / дата:
- Версии правил, схемы и шаблона:
- Всего / успешно / ошибки / карантин / пропущено:
- Партии и checkpoints:
- Повторные запуски и причины:
- Метод и размер выборки:
- Дефекты по критичности:
- Ограничения и непроверенные области:
- Место экспорта и контрольная сумма:
- Решение о приемке:
```
