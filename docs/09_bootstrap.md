# Project Bootstrap Protocol

## Процесс

1. Изучить доступные материалы до вопросов.
2. Определить тип проекта и предложить уровень Lite/Standard/Advanced/Program.
3. Инвентаризировать источники, даты, владельцев, права и дубли.
4. Выделить критические пробелы, которые могут изменить архитектуру или сделать действие опасным.
5. Создать максимально полный Draft: Charter, DNA, SoT, Knowledge Map, Glossary, Decision/Assumption/Risk Logs, Workstream Map.
6. Все некритические пробелы оформить как проверяемые допущения со сроком.
7. Задать одним пакетом не более пяти критических вопросов.
8. Сформировать первый Stage Brief, Context Manifest и Work-задачу.
9. Предложить автоматизации, но не включать их до стабильного ручного цикла.
10. Указать одно ближайшее действие, владельца и критерий завершения.

## Универсальный промпт инициализации

```text
Включи Project OS и инициализируй этот проект в ChatGPT Work.

Сначала полностью изучи доступные файлы, ссылки, инструкции и сообщения. Не начинай
с анкеты. На их основе создай максимально полный черновик системы проекта:
1) тип проекта и рекомендуемый уровень Lite/Standard/Advanced/Program с причиной;
2) Project Charter и Project DNA;
3) инвентаризацию источников и Source of Truth Registry;
4) Knowledge Map и Glossary;
5) Decision, Assumption и Risk Logs;
6) Workstream Map и жизненный цикл с gates;
7) список пробелов и конфликтов по критичности;
8) первый Stage Brief, Context Manifest и контракт первой Work-задачи;
9) критерии успеха/остановки и ближайшее действие;
10) разумные предложения автоматизации.

Отделяй факты от допущений. Не придумывай отсутствующие услуги, условия, цены,
права или продуктовые функции. Некритические пробелы внеси как допущения с планом
проверки. После черновика задай одним блоком только критические вопросы, без которых
высок риск принципиально неверной или опасной работы (не более пяти). Все действия
с внешними системами, публикацией, платежами, удалением, секретами или юридическими
последствиями оставь на явное утверждение человека.

Заверши таблицей: созданный артефакт -> статус -> владелец -> следующий шаг.
```

## Проверка Bootstrap

Bootstrap завершен, если владелец понимает цель и границы; каждый критичный тип данных имеет SoT либо открытый блокирующий gap; допущения видимы; первая задача исполнима без полного архива; условия Approval и Stop определены.
