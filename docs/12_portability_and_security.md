# Переносимость и безопасность

## Portable Project Pack

Пакет не должен требовать память исходной модели. Содержимое:

1. `README_FIRST.md`: цель, текущий статус, дата среза, владелец.
2. Approved Project DNA.
3. Source of Truth Registry с доступностью источников.
4. Glossary и Knowledge Map.
5. Decision Log (активные решения и замененные версии).
6. Open Issues, Assumptions и активные риски.
7. Current Stage Brief, Context Manifest и следующий шаг.
8. Минимальный набор необходимых исходников.
9. Quality Standard и правила поведения AI.
10. Manifest файлов: имя, версия, статус, hash при необходимости, классификация данных.

## Протокол переноса

1. Зафиксировать срез и остановить параллельные смысловые изменения.
2. Собрать только Approved и явно необходимые Draft-материалы.
3. Удалить/заменить секреты и лишние персональные данные.
4. Проверить ссылки и приложить разрешенные копии, если доступ не переносится.
5. Отметить платформенные инструкции как adapter-only.
6. Создать manifest и контрольные суммы для критичных файлов.
7. В новой платформе попросить сначала пересказать ограничения и открытые риски, не выполнять работу.
8. Сверить понимание с Handoff Checklist.
9. Выполнить малую пробную задачу и сравнить результат.
10. Только после проверки продолжить этап.

Не переносить без проверки: скрытые допущения; непроверенные факты; платформенные команды; ссылки без доступа; Superseded/Archived; токены, пароли, ключи; персональные данные без основания; полный архив вместо целевого контекста.

## Классы данных

| Класс | Примеры | Правило |
|---|---|---|
| Public | опубликованный сайт, публичный пресс-релиз | можно использовать в разрешенной задаче; проверять дату/лицензию |
| Internal | внутренний план, черновик без секретов | только утвержденный workspace/получатели |
| Confidential | цены до публикации, договоры, клиентские данные | минимизация, явные права, без публичных сервисов/ссылок |
| Restricted | пароли, ключи, особо чувствительные данные | не загружать; использовать секрет-хранилище/маскирование и отдельный процесс |

Классификация наследуется производным артефактом по наиболее чувствительному входу, пока владелец данных явно не утвердит снижение класса.

## Security Gate

Перед передачей или действием проверить: цель и минимальность данных; получателя; разрешение; план/регион/admin settings; секреты; персональные данные; внешние источники; публичность результата; журналирование; возможность отката. Коммерческие условия не публикуются и не отправляются без сверки с действующим SoT и человеком.

## Веб-поиск

Публичный веб используется как внешний источник, а не как автоматическая истина. Для динамических сведений сохраняются URL, дата доступа и регион. Внутренние запросы не должны раскрывать клиентские имена, секреты или конфиденциальную стратегию. Если workspace использует ограниченный/кэшированный поиск, покрытие и свежесть считаются ограничениями исследования.
