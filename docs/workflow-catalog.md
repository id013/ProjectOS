# Workflow Catalog

Start with the result you need, not with the full methodology.

| Workflow | Primary output | Recommended mode | Critical gates |
|---|---|---|---|
| Working document | reviewable document | Lite | facts, editing, human review |
| Market research | evidence pack and conclusions | Standard | source quality, dates, conflicts |
| Customer discovery | ICP, pains, and evidence | Standard | privacy, sample bias, claim accuracy |
| Website transformation | architecture, content, release pack | Advanced | SEO, CRO, editorial, publication |
| Batch page production | manifest, pages, QA report | Advanced | uniqueness, factuality, sampled QA |
| Data analysis | clean dataset and conclusions | Standard | original preservation, formulas, sampling |
| Recurring monitoring | scheduled report | Standard | availability, notification, stop rule |
| Technical change | diff, tests, handoff | Standard or Advanced | security, tests, review |

## Workflow metadata

Every workflow card should declare:

- domain;
- expected output;
- operating surface;
- duration;
- risk;
- maturity;
- required approval;
- ProjectOS mode.

## Promotion rule

A new workflow remains experimental until it has either two successful applications or one formal pilot with documented QA. Stable workflows need a named owner, evidence, version history, limitations, and rollback.
