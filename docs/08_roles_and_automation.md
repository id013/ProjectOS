# Роли, Work-задачи и автоматизация

## Библиотека ролей

Общие запреты всех ролей: не выдумывать факты; не обходить права; не менять Approved-источник молча; не выполнять внешнее/необратимое действие без нужного согласования.

| Роль | Назначение | Вход -> выход | Разрешено / нельзя | Эскалация | Автономность и среда |
|---|---|---|---|---|---|
| Project Initiator | превратить запрос в проект | материалы -> Charter, уровень, gaps | диагностика / не утверждает цель за владельца | критические границы неизвестны | Work, автономно до Draft |
| Knowledge Librarian | нормализовать знания | sources -> map, glossary, registry | классификация / не разрешает смысловой конфликт | неоднозначная сущность | Work или пакетный процесс |
| Source Auditor | проверить происхождение | реестр -> reliability report | сверка дат/прав / не объявляет истиной по удобству | C2/C3 конфликт | отдельная Work-задача |
| Context Curator | собрать целевой контекст | brief+SoT -> Manifest | включать/исключать с причиной / не скрывает конфликт | отсутствует критичный SoT | Work, автономно |
| Project Planner | построить путь | Charter -> workstreams/stages | зависимости и gates / не обещает ресурсы | бизнес-компромисс | Plan/Work, Draft |
| Researcher | собрать доказательства | вопрос -> evidence pack | поиск и синтез / не заменяет domain approval | источники не подтверждают тезис | Work, web/apps по правам |
| Domain Expert | применить предметные правила | evidence -> expert analysis | интерпретация / не маскирует неопределенность | высокий профессиональный риск | Work + человек при critical |
| Producer | создать артефакт | Manifest -> Draft | производство / не утверждает себя | требования конфликтуют | Work; Codex только для разработки |
| Critic | искать слабости | Draft -> defect list | adversarial review / не переписывает без маркировки | C3 | отдельная Work-задача |
| Fact Checker | проверить утверждения | claims -> evidence matrix | первичные источники / не проверяет стиль вместо фактов | нет доступа/источника | Work с web/apps |
| Consistency Auditor | сверить SoT/DNA | artifacts -> conflict report | трассировка / не выбирает бизнес-вариант | равноправный конфликт | Work, автономно до решения |
| Quality Controller | провести Gate | artifact+checks -> verdict | pass/rework/block / не снижает порог задним числом | accepted risk нужен владелец | отдельная Work-задача |
| Documentation Agent | обновить память | outputs -> registries | механическая фиксация / не создает новое решение | вывод неясен | Work, автономно |
| Handoff Agent | передать контекст | stage records -> pack | сжатие с прослеживаемостью / не тащит весь архив | критический пробел | Work, автономно |
| Retrospective Agent | найти системные уроки | logs -> retro/proposals | анализ причин / не меняет baseline | риск изменения OS | Work + approval |
| Project OS Maintainer | управлять методологией | proposal+test -> release | версия/rollback / не принимает свой proposal единолично | baseline change | человек утверждает |

Качество роли оценивается по полноте выхода, прослеживаемости, соблюдению границ и явной неопределенности — не по объему текста.

## Индивидуальные критерии качества

| Роль | Проверяемый критерий |
|---|---|
| Project Initiator | Charter позволяет владельцу однозначно принять/изменить цель; критические gaps не скрыты |
| Knowledge Librarian | сущности имеют стабильные ID; дубли/конфликты не потеряны при нормализации |
| Source Auditor | каждый verdict о надежности подкреплен происхождением, датой, владельцем и областью |
| Context Curator | в Manifest есть весь минимальный и нет необъяснимого archive/noise; исключения обоснованы |
| Project Planner | каждый этап имеет вход, выход, зависимость, DoD, Gate и владельца |
| Researcher | тезисы прослеживаются к источникам; метод, срез, ограничения и противоположные evidence видимы |
| Domain Expert | предметные выводы отделены от данных; предел компетенции и high-risk review указаны |
| Producer | артефакт соответствует acceptance без незаявленного изменения scope/SoT |
| Critic | находки конкретны, воспроизводимы, приоритизированы; вкусовые замечания отделены от дефектов |
| Fact Checker | claim-evidence matrix покрывает все значимые проверяемые утверждения |
| Consistency Auditor | конфликт связан с точными версиями и dependency impact, а не только описан словами |
| Quality Controller | verdict следует заранее заданным порогам; непроверенное не считается пройденным |
| Documentation Agent | результат воспроизводится по документам; новые записи не меняют смысл решения |
| Handoff Agent | принимающий может назвать цель, SoT, запреты и следующий шаг без исходного чата |
| Retrospective Agent | предложения опираются на причины и метрики, а не на единичное раздражение |
| Project OS Maintainer | каждое baseline-изменение имеет пилот, approval, версию и рабочий rollback |

## Размещение функций

| Среда | Подходящие функции |
|---|---|
| Одна Work-задача | исследование, план, документ, таблица, презентация, QA одного результата |
| ChatGPT Project | долговременная группировка чатов, файлов и инструкций; не замена формальному SoT |
| Desktop Work | задачи с разрешенными локальными файлами/приложениями |
| Cloud Work | облачные файлы, исследования, deliverables, задачи по расписанию при доступности |
| Codex | только разработка: репозиторий, код, тесты, технические изменения |
| Постоянный агент/расписание | мониторинг дат, ссылок, условий, статусов и зависимостей |
| API/n8n | высокочастотный детерминированный обмен, маршрутизация, webhooks, пакетные задания |
| Человек | права, приоритеты, обещания, риск, публикация, необратимые действия |

## Лестница автоматизации

1. ручной промпт;
2. повторяемый шаблон;
3. Work-задача с подключенным приложением;
4. Scheduled Task;
5. API/n8n с логами, идемпотентностью и approval;
6. постоянный монитор с безопасным fallback.

Повышать уровень только после 3–5 стабильных ручных циклов, измеримого выигрыша и определенного владельца ошибок. Автоматизация не должна утверждать критический результат только потому, что завершилась технически.
