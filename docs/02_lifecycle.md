# Жизненный цикл

Для каждого этапа переход разрешен только при выполненном Gate. Колонки «выход/готовность» одновременно являются минимальным чек-листом.

| Этап | Цель и входы | Ключевые действия | Выход / критерий перехода | Типовая ошибка |
|---|---|---|---|---|
| 1. Инициация | превратить намерение в управляемую цель; вход: запрос, ограничения | определить результат, границы, владельца, уровень | Draft Charter; понятны ценность и стоп-критерии | начинать производство без границ |
| 2. Диагностика | понять, чего не хватает | экспресс-аудит, вопросы только по критическим пробелам, допущения | Gap list, Assumption Log; нет скрытого критического пробела | засыпать владельца вопросами |
| 3. Сбор источников | собрать доказательную базу | инвентаризация, метаданные, права, даты, дубли | Source Registry; каждый критичный тип данных имеет источник | копировать данные без происхождения |
| 4. Нормализация | сделать знания сопоставимыми | сущности, термины, дедупликация, конфликты | Knowledge Map, Glossary, conflict table | «склеивать» противоречия догадкой |
| 5. Планирование | построить проверяемый путь | этапы, зависимости, владельцы, Gates, batches | Workstream Map и первый Stage Brief | планировать без критериев приемки |
| 6. Выполнение | создать результат | Context Manifest, производство, фиксация новых фактов/решений | Draft artifact + evidence list | смешать несколько целей в одной задаче |
| 7. Проверка | независимо найти дефекты | critic, fact check, consistency, domain checklist | QA Report; критические дефекты закрыты | считать самоперечитывание независимой проверкой |
| 8. Утверждение | принять ответственность | сравнить с критериями, остаточные риски, версия | Approved artifact + Decision Log | утверждать устно без фиксации |
| 9. Публикация/внедрение | безопасно доставить результат | preflight, backup/rollback, публикация, smoke test | ссылка/акт внедрения, журнал релиза | необратимое действие без согласования |
| 10. Поддержка | сохранить актуальность | владелец, дата пересмотра, мониторинг изменений | актуальные SoT и зависимости | «готово навсегда» |
| 11. Архивация | убрать шум, сохранить историю | supersede, manifest, read-only archive | рабочий контекст очищен, история доступна | удалять старую версию без ссылки на замену |
| 12. Ретроспектива | извлечь уроки | причины ошибок, потери контекста, стоимость контроля | Retrospective + change proposals | менять систему по единичной эмоции |
| 13. Обновление OS | улучшить метод без дрейфа | гипотеза, риск, тест, approval, rollback | новая baseline-версия или отклонение | самовольное переписывание правил |

## Контрольные вопросы любого Gate

1. Соответствует ли выход цели этапа и Project DNA?
2. Какие утверждения являются фактами, а какие допущениями?
3. Есть ли источник, дата, владелец и версия?
4. Что изменилось и какие зависимости теперь устарели?
5. Какие риски остаются и кто их принял?
6. Можно ли воспроизвести решение без истории этого чата?
7. Нужна ли проверка или санкция человека до следующего действия?
