# Context Engineering

## Четыре слоя

- **Минимальный** — без него результат, вероятно, неверен: Stage Brief, Project DNA, действующий SoT, критерии приемки.
- **Рабочий** — заметно улучшает качество: связанные решения, словарь, релевантные исследования, шаблон результата.
- **Справочный** — нужен только для отдельных проверок: архивные примеры, вторичные обзоры, соседние workstreams.
- **Исключенный** — устаревший, конфликтующий без маркировки, непроверенный, нерелевантный, избыточный или запрещенный по доступу.

## Алгоритм отбора

1. Разложить цель на сущности, решения и требуемые доказательства.
2. Добавить обязательные управляющие документы: Brief, DNA, Quality Standard.
3. Для каждой сущности найти действующий SoT в реестре.
4. Отфильтровать `Superseded/Archived`, если задача не историческая.
5. Исключить материалы без необходимых прав доступа.
6. Поднять приоритет Approved, свежих, первичных и прямо зависимых источников.
7. Добавить конфликтующие источники только вместе с описанием конфликта.
8. Оценить шум: документ включается, если ожидаемая польза выше риска отвлечения.
9. Сжать длинные источники в целевые выдержки, сохранив ссылку, дату и границы сокращения.
10. Записать набор и причины в Context Manifest.

## Скоринг при большом числе документов

`Score = 4*обязательность + 3*статус + 2*надежность + 2*связь + свежесть - 3*конфликт - 2*шум - размер`.

Каждый показатель нормируется 0–2. Документ с неразрешенным критическим конфликтом не становится SoT независимо от score. Score — фильтр внимания, не автоматическое решение об истинности.

## Контекстная гигиена

- Не включать весь архив «на всякий случай».
- Не использовать резюме без ссылки на исходник как первичный источник.
- Отмечать дату среза для цен, условий, законодательства и продуктовых функций.
- Не смешивать сведения разных клиентов, партнеров, регионов или тарифов.
- При изменении SoT заново собрать Manifest для активных задач.
- Перед передачей наружу удалить секреты и лишние персональные данные.
